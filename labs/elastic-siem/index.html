Lab 5 — Elastic SIEM, Fleet and endpoint telemetry¶

Build guide — not yet lab-tested

1. Topology and sizing¶

Use a fresh supported Ubuntu Server VM on the Windows x64 PC: 4–8 vCPU, 12–16 GB RAM and 150–200 GB SSD-backed virtual disk as a home-lab starting point. Run Elastic alone initially. This is a single-node learning deployment, not production HA. Keep Elasticsearch and Kibana on the same version. Check the current Elastic support matrix for the selected OS and architecture.

2. Install Elasticsearch 9.x from the official APT repository¶

The following follows Elastic's currently documented 9.x Debian package instructions. If a new major release is available when you build, use that major version's official instructions and change the repository path consistently.

sudo apt-get update
sudo apt-get install -y wget gnupg apt-transport-https
sudo install -d -m 0755 /usr/share/keyrings
wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | sudo gpg --dearmor -o /usr/share/keyrings/elasticsearch-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/elasticsearch-keyring.gpg] https://artifacts.elastic.co/packages/9.x/apt stable main" | sudo tee /etc/apt/sources.list.d/elastic-9.x.list
sudo apt-get update
sudo apt-get install -y elasticsearch

Start and enable Elasticsearch:

sudo systemctl daemon-reload
sudo systemctl enable elasticsearch.service
sudo systemctl start elasticsearch.service
sudo systemctl status elasticsearch --no-pager
sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic

Save the generated password securely. First startup enables security and creates TLS certificates. Do not disable authentication or TLS.

Verify local HTTPS (enter the password when prompted):

curl --cacert /etc/elasticsearch/certs/http_ca.crt -u elastic https://localhost:9200

A successful response includes cluster/node and version details. If the certificate path differs, inspect the package output and actual certificate location. Do not use an insecure TLS bypass as a permanent workaround.

3. Install Kibana from the same repository¶

Use the same Elastic 9.x APT repository and install the same release family:

sudo apt-get update
sudo apt-get install -y kibana
sudo systemctl daemon-reload
sudo systemctl enable kibana.service
sudo systemctl start kibana.service
sudo systemctl status kibana --no-pager

Generate a Kibana enrollment token on the Elasticsearch host:

sudo /usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s kibana

Open the Kibana setup URL shown by the service status, enter the enrollment token, complete the verification-code step, then sign in with the elastic account. Enrollment tokens expire; generate a new token if required. Follow the current Kibana Debian installation guide if the setup wizard differs.

Restrict Kibana access to MGMT. Do not expose port 5601 to the public Internet.

4. Configure Fleet¶

  1. Open Kibana from the management workstation.
  2. Navigate to Management → Fleet.
  3. Follow the Fleet Server setup wizard for the deployment type.
  4. Use a stable lab DNS name/IP reachable from endpoint VMs.
  5. Create the Fleet Server policy and enrollment token.
  6. Use the exact install/enrollment command generated by the wizard on each endpoint.
  7. Keep TLS trust configured. Treat enrollment tokens as secrets; never publish them.

For a small lab, Fleet Server may share the Ubuntu VM, but check current Fleet sizing and support requirements. If the wizard or load requires a separate Fleet Server, create another VM.

5. Windows Sysmon integration¶

  1. On PSV-W11-01, install Sysmon using Microsoft's official instructions.
  2. Confirm Event Viewer → Applications and Services Logs → Microsoft → Windows → Sysmon → Operational receives Event ID 1.
  3. In Kibana → Integrations, add the Windows integration to the Windows endpoint policy.
  4. Enable Sysmon Operational channel collection.
  5. Wait for the policy to apply, then launch Notepad on the endpoint.
  6. Inspect the raw event in Discover and record the actual data stream and field names.

Do not assume dataset/field mappings are identical across integration releases. Inspect the raw document.

6. Linux endpoint integration¶

  1. Add the System integration to a Linux endpoint policy.
  2. Enrol the Ubuntu endpoint using the Fleet-generated command.
  3. Confirm system metrics arrive.
  4. Add Auditd integration only after auditd is installed and configured on the endpoint.
  5. Confirm the audit source and event fields separately from system metrics.

7. Search and test¶

After confirming the real data stream and ECS mappings, a starting KQL search for Sysmon process creation is:

event.code : "1" and process.name : "notepad.exe"

Create a test detection only after verifying the fields. The Phase 5 PowerShell analytic assumes ECS process fields; adapt it to the raw event and dataset actually ingested. Run positive and negative tests and record the raw event, alert, timestamps, agent version and ingest delay.

8. Troubleshooting¶

sudo journalctl -u elasticsearch -n 100 --no-pager
sudo journalctl -u kibana -n 100 --no-pager

For offline agents, check Fleet URL resolution, TLS trust, firewall, policy and the agent status command. For no Sysmon data, first prove the local event exists; then check agent integration, channel subscription, ingest errors and data stream. For high memory pressure, reduce active VMs; do not arbitrarily change JVM heap.

9. Cleanup¶

Unenrol agents through Fleet, stop services cleanly and retain only sanitised evidence. Follow Elastic's package removal/data-directory procedures if deleting the lab. Never commit passwords, tokens, certificates or production telemetry.
