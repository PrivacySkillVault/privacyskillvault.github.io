Security and limitations

  • Encryption: AES-256-GCM using a random key generated in this browser.
  • Files travel over a WebRTC data channel; no file content is sent to PSV or the signalling service.
  • The link contains the decryption key in its URL fragment. Anyone who obtains the complete link may attempt to connect.
  • The sender must approve the recipient and remain online. This is not an asynchronous file-hosting service.
  • PeerJS's public signalling broker is used to establish the connection. It handles connection metadata, not the encrypted file payload; its availability and privacy are subject to that service.
  • WebRTC may fail on restrictive networks where direct connectivity is blocked. This version does not use a third-party TURN relay.
  • After successful transfer, the session closes. This cannot prevent the recipient from copying or redistributing the downloaded file.
